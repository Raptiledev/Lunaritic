LUNARIS rebuild prompts
NASA Space Apps 2026 · Lunar Landing Site Navigator · Team Alpha 8

How to use this file
--------------------
Paste ONE prompt into a fresh coding session. Wait until that phase builds,
runs, and its tests pass. Then paste the next prompt into the same session.
Do not paste the whole file at once. The app is a Next.js site plus a
Python calculation service. Starting at Next.js is prompt 1. The science
cannot live in the browser alone, so prompt 2 creates the backend before
any terrain number is shown.

Paste the STANDING RULES at the top of every prompt, then the phase text.


========================================================================
STANDING RULES  (paste above every phase)
========================================================================

You are building LUNARIS, a terrain-aware lunar south-polar landing tool
for Team Alpha 8. It is not an official NASA tool and must say so in the
interface. Do not draw NASA logos, flags, or mission identifiers.

Build only this phase. Do not start the next phase.

Science rules:
- Show a number only when it was computed from real inputs or from a test
  fixture that is labelled synthetic. Never fill a missing dataset field
  with a guess. Unknown stays null and the UI says "not recorded" or
  "not computed".
- Sunlight is geometry, not electrical power. Earth above the horizon is
  not a radio link. Scores are weighted geometry, not a mission-success
  probability and not a machine-learning score.
- Hazard thresholds are illustrative, not NASA requirements.
- Amber means the Sun only. Blue means Earth only. Green, amber-orange,
  and red appear only on hazard classes. Everything else is a neutral
  dark "regolith" interface.
- Do not commit frontend/node_modules, backend/.venv, backend/venv,
  GeoTIFFs, or SPICE kernels.
- Python 3.11+. Next.js 14 App Router, TypeScript, Tailwind. No extra
  UI framework.

PROMPT 3 — LOLA terrain engine
========================================================================

Implement the Site01 DEM loader. Do not download files in this phase.
The operator places GeoTIFFs in backend/app/data/dem/. Required file is
the surf GeoTIFF. ldec, toterr, slperr, and slp are optional.

Read with rasterio. Refuse a file whose CRS is not south polar
stereographic on a sphere of radius 1737400 m with latitude of origin
-90. Pixel size must be square. Map nodata to NaN.

Projection helpers, tested:
  lat/lon (east-positive) <-> polar stereographic metres
  using +proj=stere +lat_0=-90 +lat_ts=-90 +lon_0=0 +k=1 +R=1737400.

From the surf grid compute:
  slope and aspect by Horn 3x3 on the 5 m grid
  hillshade
  roughness as RMS residual from a local plane, 5x5 pixels
  local relief
Hazard class is the worst of slope and roughness. Default illustrative
gates: slope caution 5 deg, slope high 10 deg, roughness caution 0.25 m,
roughness high 0.5 m. If slperr is present, a pixel whose slope
uncertainty exceeds 5 deg is not given a confident class. These gates
are not NASA requirements. Label them illustrative in the API notes.

Endpoints under /api/terrain:
  GET /sites
  GET /{site_id}/layer/{layer}.png   layers: elevation, slope, hillshade,
      roughness, hazard, lola_count, z_uncertainty
  GET /{site_id}/legend/{layer}
  GET /{site_id}/point?x=&y=  and also lat/lon
  GET /{site_id}/summary?x=&y=&radius_m=
Point payload includes row, col, lat, lon, height, slope, aspect,
roughness, hazard, LOLA return count when ldec exists, height uncertainty
when toterr exists. Missing optional layers return null, not zero.
Outside the tile is HTTP 422. Missing surf is HTTP 404.

Tests use a tiny synthetic plane on the real Site01 grid geometry and
must say in the test name or docstring that the grid is synthetic, not
lunar. Also test CRS rejection and lat/lon of the real Site01 corners
against the known bounds x from -19000 to -3000 m, y from -20000 to
-4000 m. Add scripts/inspect_dem.py to print metadata of whatever is
in the dem folder. Gitignore backend/app/data/dem except .gitkeep files.

PROMPT 5 — Terrain horizon
========================================================================

Add a horizon service. For one observer on the DEM, cast rays at 1 degree
azimuth steps, sample every 5 m out to 20 km. Azimuth is clockwise from
local lunar north. On the polar stereographic grid, grid azimuth equals
true azimuth plus east longitude. Elevation of a sample uses the sphere,
not a flat plane:

  r0 = R + z_observer, r1 = R + z_sample, theta = distance / R
  elevation = atan2(r1*cos(theta) - r0, r1*sin(theta))

R is 1737400 m. The horizon in that direction is the maximum elevation
along the ray. If the ray leaves the tile before 20 km, mark it
incomplete: that horizon is a lower bound because terrain outside the
tile is unknown.

Also compute the visible fraction of a disk given horizon elevation,
disk-centre elevation, and angular radius. GET
/api/terrain/{site_id}/horizon returns the profile, incompleteness
flags, and the observer lat, lon, and height.

Tests: synthetic ridge on the Site01 grid geometry, labelled synthetic.
A wall in one direction must raise only that sector. A ray that exits
the grid must be flagged incomplete. Wire a horizon panel on the
Explorer for the selected point. If the point is missing, the panel
says the horizon is not computed. It must not draw a fake skyline.

  naif0012.tls, pck00011.tpc, moon_080317.tf, moon_assoc_me.tf,

If any file is missing, the endpoint returns 503 naming the missing

Observer position is height above the 1737.4 km sphere, expressed in
MOON_ME. Use spkcpo with aberration correction LT+S. Azimuth is
atan2(east, north), clockwise from lunar north, 0 to 360. Elevation is
asin(up / range). Apparent angular radius uses solar radius 695700 km
and Earth equatorial radius 6378.137 km. elevation_deg is the disk
centre, not the limb.

GET /api/ephemeris/status and GET /api/ephemeris/track with lat, lon,
height_m, start, stop, step_min, for bodies SUN and EARTH. Cap the
sample count. Times outside 1900-2050 return a clear error.

Tests skip when the kernels are not installed. Do not commit kernels.
Gitignore backend/app/data/kernels except .gitkeep.

PROMPT 7 — Visibility over a mission window
========================================================================

Combine the horizon profile with the SPICE track. At each time step:
  Sun is lit if any part of the solar disk is above the terrain horizon.
  sunlight_mean is the time average of the visible fraction of the disk.
  Earth is in view if at least half of Earth's disk is above the horizon.
Build contiguous periods and the longest darkness.
State the limits in the response notes:
  an incomplete horizon makes sunlight and Earth visibility upper bounds
  and darkness a lower bound; events are timed only to half a step;
  there is no power model and no link budget.

GET /api/analysis/{site_id}/visibility.
The Analysis page uses the mission target and window. A button runs the
request. Before it is run, show "Not computed". Show the Sun and Earth
elevation series against the horizon in their colours, the lit fraction,
the longest darkness, and the notes. Cache the last result in React
context so later pages can read it, and mark it stale if the target or
window changes.

PROMPT 10 — Explainable comparison
========================================================================

Scoring is two layers.
Hard gates, same numbers as the planner. A candidate that fails is
ineligible. Still show its soft score so the failure is visible.
Soft score is a weighted average of four factors, each from 0 to 1:
  sunlight = lit fraction
  darkness = 1 - longest_dark_hours / mission_hours, clipped
  earth = in-view fraction
  terrain = favorable-pixel fraction
Default weights 0.35, 0.25, 0.20, 0.20. Negative weights are rejected.
Normalise to sum to 1. The response includes each contribution
weight times score, so the total can be read by hand.
The overall number is not a probability.

POST /api/analysis/{site_id}/compare with up to 6 candidates.
The Compare page lets the user edit gates and weights, run the
comparison, and see eligible and ineligible rows. No black-box score.
